| --- | --- | --- |
| Nginx | 80/443 | 公网入口、TLS、路由 |

### 关键规则

1. Node 代理的 `proxy_pass` **不能**写尾斜杠：`proxy_pass http://127.0.0.1:3030;`
2. 通用 CSS/图片正则 location 必须转发给 Node，否则会命中面板本地 404，导致无样式页面。
3. 访客分析：已自动记录，**无弹窗、不请求定位**。
4. 请求/响应正文审计按站点开关。后台把 Audit probe 设为 On 后才会落盘；每个站点最多保留 300 条、64MB，超出后删最旧记录，避免再次占满磁盘。
5. 代理会自动改写 HTML/CSS/JS/JSON 中的站点 URL，并处理 SPA 动态加载的资源；压缩文本响应会先解压再改写和审计。
6. 审计写入按站点异步排队，不阻塞页面响应；后台查看审计时可能有极短的落盘延迟。
7. `hacket.top` 的 HTTPS 虚拟主机直接转发到 `127.0.0.1:3030`，不要再经由 IP 虚拟主机转发，否则会增加一跳并污染 Host。
8. 默认上游不可达时，Node 会在 4 秒后使用 `/etc/iframe-host/fallback-cache.json` 中的预热页面、CSS、脚本和图片；同一上游会熔断 30 秒，避免浏览器的并发资源请求反复卡住。执行 `npm run refresh-fallback-cache` 可重新生成该缓存，部署脚本检测到 `.cache/fallback-cache.json` 时会一并上传。

## 管理后台：中英文与内置帮助

- 登录后打开 **全局设置 → 界面语言**，选择 **中文 / English** 即可切换整个后台和使用说明；不再在登录页、顶部导航单独显示语言切换按钮。
- 选择结果保存在当前浏览器的 `localStorage`（键 `proxyAdminLang`），刷新或重新登录后保持。
- 语言选择立即生效，不需要保存服务器设置；修改管理员账号、密码或采集上限时仍需要点击 **保存全局设置**。
- 登录后的 **使用说明** 按钮提供统一说明入口，页面顶部的目录可跳转查看站点字段、保存错误、全局设置、语言切换、兼容与审计、访客分析、替换规则、请求 / 响应键值脚本、URL 拦截脚本、排错和安全提示。
- 站点编辑和全局设置弹窗也提供 **使用说明** 按钮；查看后点击 **返回站点** 会返回原弹窗，保留尚未保存的输入。
- 语言切换只影响管理后台界面，不会改变被代理站点的页面内容。

### 站点 ID 报错处理（2026-11-13）

- `ID` 是内部标识，不是显示名称或网址；允许 1–64 位英文字母、数字、连字符和下划线，必须以字母或数字开头，例如 `my-site`。中文名称填写在 **显示名称**。
- 点击保存时先在浏览器检查 ID、显示名称和 HTTPS 地址，错误时高亮、聚焦并滚动到对应字段，同时显示当前语言的解释；未通过检查不会发送保存请求。
- 服务端仍保留校验；ID 重复、前缀冲突、错误登录凭据等常见错误会转换为当前界面语言，不再直接显示截图中的 `site id: 1-64 chars [A-Za-z0-9_-]`。
- `npm run check` 包含后台脚本语法、词条对齐、错误翻译、表单校验和说明目录回归测试；完整代理回归仍运行 `node test-multisite-integration.js`。

## 站点 URL 拦截脚本

- 每个站点可在「编辑站点 → URL 拦截脚本」中单独开启，支持普通文本或正则匹配。
- 请求命中规则后，代理不会访问上游，而是直接在 Node 进程内执行配置的 JavaScript，并返回脚本生成的结果。
- `request` 提供 `method`、`path`、`query`、`url`、`headers`、`cookies`、`body`；`site` 提供当前站点信息；`console.log` 输出到服务日志。
- 脚本需同步执行，返回字符串，或 `{ status, headers, body, content_type }`；默认超时 1000ms，可配置 50–5000ms。
- 拦截脚本属于管理员可信代码，仅在明确需要替换上游响应时开启；关闭开关后立即恢复为正常代理。

## API 透传模式

入口：**编辑站点 → API 透传**。每站独立，默认关闭，不自动改动现有生产配置。

例如站点目标为 `https://8888ok.cc`、代理前缀为 `/666`，客户端填写 API Base URL `https://hacket.top/666/v1`，`/666/v1/chat/completions` 会转发至原站 `/v1/chat/completions`。客户端必须使用原站有效的 API Key；网页登录 Bearer Token 不保证可用于 API。不做额外计费、不自动提供或生成 Key。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| API 透传模式 | 关闭 | 仅开启且路径命中时走 API 分支，其余仍为网页代理 |
| 上游路径前缀 | `/v1` | 每行一个，最多 32 项；不带 `/666`；`/v1` 匹配自身及其子路径，但不匹配 `/v10`；`/` 表示整个站点 |
| 首响应超时 | 120 秒 | 等待上游响应头的限时，不是整个生成任务的总时长；范围 1–3600 秒 |
| 流空闲超时 | 120 秒 | 建连并收到响应头后，连接持续没有数据的限时；持续有数据的流不会因总时长超过此值而截断；范围 1–3600 秒 |
| 应用请求键值规则 | 关闭 | 开启后执行本站启用的请求规则，仍受键值脚本总开关控制；正文规则会缓冲请求且仍受 1 MiB / 15 秒等原有限制 |
| 改写 API Origin / Referer | 关闭 | 默认保留调用方的值；需要兼容原站时才开启，使用现有上游头改写逻辑 |

API 分支转发方法、查询参数、Authorization、内容编码和正文，不对响应做网页 URL 替换、JSON 值脚本、验证码注入、正文审计或降级缓存。不执行 URL 拦截脚本、OAuth 浏览器重定向。响应按原始字节流转发（含 SSE、压缩和二进制），保留原站状态码及业务响应头，去除逐跳头，设置 `X-Accel-Buffering: no` 和 `Cache-Control: no-store`。客户端断开会停止上游传输，不自动重试生成或支付请求。超时未收到响应头返回 504；响应开始后发生空闲超时或断流会中断流，不伪造一个 JSON 成功响应。

关闭透传模式，或访问未匹配的路径，立即恢复原有网页逻辑。配置只决定传输方式，不新增身份校验、跨域许可或原站 API 权限，也不支持 WebSocket。浏览器跨域调用仍需原站允许的 CORS 策略；普通桌面 / 服务端 API 客户端不依赖浏览器 CORS。

部署前还应核对外层 Nginx / CDN / 负载均衡器的超时和缓冲配置。本服务配置不能延长外层代理的超时。API 模式不会写入本站正文审计，但外层访问日志、第三方上游自身日志不受这个开关控制。不要把 API Key 放在 URL 查询串。

排错：先用客户端只调用轻量的模型列表等接口验证链路，再验证流式输出。不用创建充值订单或触发付费验证码来测试透传。页面抓包看到的是浏览器发给本站的原始请求，不是服务器应用可选请求规则后的上游请求。

## 站点请求 / 响应键值脚本

### 功能与调试分开控制

- **键值脚本总开关**（`value_rules_enabled`）：关闭后跳过本站所有请求 / 响应键值规则，不匹配、不运行脚本、不为规则缓冲请求正文；保留规则内容。旧配置默认开启，确保原规则不失效。
- **每条规则开关**：总开关开启时，仍只执行已开启且 URL 命中的规则。
- **站点调试日志**（`debug_enabled`）：默认关闭，不影响脚本改写、验证码功能或费用额度。关闭时不收集验证码事件，不发浏览器诊断上报、不写诊断 sessionStorage、不输出脚本阶段日志；已打开的页面须刷新才能停止旧脚本上报，服务器会立即拒绝关闭后的上报。
- 调试开启后只记录事件与阶段元数据，不记录脚本的 `console.log` 参数、密码、Cookie、请求头或验证码结果。脚本日志每站每分钟最多 60 行，验证码每站每分钟最多 120 行；浏览器每页最多 40 个不同事件、每票据上报最多 48 条，验证码内存总量最多 1000 条，后台每次最多显示本站 50 条。
- 诊断仅手动点击检查，不新增后台自动轮询，也不因为开启调试而创建付费任务。排错完关闭即可；已有 systemd 日志按服务器日志保留策略处理，不会因关闭自动删除。
- **审计探针**独立控制，打开后会按既有规则保存有限正文，不受调试开关影响。正常使用建议调试关闭、审计按需开启；验证码服务另有开关、每小时额度和单页任务次数限制。

### 先选方向，再选位置

- **响应（默认）**：修改上游返回给浏览器的值，保留 JSON 正文键、响应头、表单字段、文本捕获四种位置。旧配置没有 `direction` 时仍作为响应规则。
- **请求**：修改发给上游的值，支持 JSON 正文键、请求头、表单字段、文本捕获，另外增加 URL 查询参数；保存格式使用 `direction: "request"`，旧的 `response_rules` 配置字段名保留以兼容已有配置。
- URL 填上游路径，不加代理前缀。例如 `/666/api/v1/auth/me` 要匹配 `/api/v1/auth/me`。请求规则按进入代理时的 URL 选定，依次修改；响应规则使用最终发送的 URL 匹配。
- 示例一：请求 → URL 查询参数，键填 `lang`，脚本填 `return "zh-CN";`，将 `?lang=en` 改为 `?lang=zh-CN`。返回 `null` 删除该参数，`undefined` 保持原值；同名重复参数会合并为一个。
- 示例二：请求 → 请求头，键填 `x-client`，脚本填 `return "my-proxy";`。Cookie 可以通过请求头 `cookie` 修改；不会写回浏览器 Cookie。
- 示例三：请求 → JSON 正文键，键填 `options.language`，脚本填 `return "zh-CN";`。JSON 保留返回值类型。
- 示例四：响应 → JSON 正文键，键填 `data.balance`，脚本填 `return Number((Number(value) * 1.5).toFixed(2));`。这只修改代理显示，不改变上游余额或扣费。
- 请求阶段 `response === null`；`request` 提供当前转发 URL、查询串、请求头和 Cookie；缓冲正文时也提供当前 `request.body`。修改必须通过 `return` 返回值，仅修改上下文对象不会改变真实请求。脚本没有 `fetch`、DOM 或 `window`，不支持异步动作。
- 无正文请求（没有 Transfer-Encoding，且 Content-Length 缺省或为 0）跳过正文规则，不要求 Content-Type，也不会凭空生成 JSON；请求头和查询参数规则仍然执行。例如取消订单的空 POST 不应被正文规则拦成 415。
- 普通文本 URL 匹配是“包含”，`/api/v1/payment/orders` 也会命中 `/api/v1/payment/orders/123/cancel`。只修改创建订单接口时，请选择正则并填写 `^/api/v1/payment/orders/?(?:\?.*)?$`，不要带 `/666` 前缀；取消等子路径不匹配。浏览器 Network / 本机 Burp 看到的是改写前的浏览器请求，不代表上游收到的值。
- 请求正文只处理非 GET/HEAD 的未压缩文本，原文及改写后正文上限均为 1 MiB，读取超时 15 秒。命中正文规则的 multipart、二进制或压缩请求返回 415，超限返回 413，读取超时返回 408；不命中正文规则的上传仍正常流式转发。
- 请求的 Host、Content-Length、Accept-Encoding、Content-Encoding、Expect 及逐跳头不允许通过规则修改，正文改写后自动重算字节长度。请求头 / 查询规则不需要缓冲正文。
- URL 拦截优先于键值规则：命中拦截时不访问上游，也不执行键值规则。规则只影响所属站点，不改变原站配置。

### 响应规则补充

- 每个站点可在「编辑站点 → Request / response value scripts / 请求 / 响应键值脚本」中单独添加多条规则，规则按顺序执行；每条规则都可以独立启用或关闭。
- 规则按上游响应 URL 与请求路径匹配（普通文本或正则，与 URL 拦截脚本使用同一套匹配方式）。只有命中的 URL 才会执行对应脚本，未命中的页面完全不受影响。
- 取值位置 `target` 支持四种：`json`（JSON 正文键路径）、`header`（响应头）、`form`（`application/x-www-form-urlencoded` 表单字段）和 `text`（正文正则）。
- JSON 键路径支持点号和数组下标，例如 `data.token`、`items[0].price`；`text` 的键是正则，存在第一个捕获组时替换捕获组内容，否则替换整个匹配。
- 脚本中可直接使用：`value`（当前取到的值）、`key`（当前键或正则）、`request`（方法、路径、查询串、URL、请求头、cookies）、`response`（状态码、上游响应头）、`site` 和 `console.log`。
- 返回值写回原位置：JSON 保留返回类型，响应头和表单会转换为字符串；返回 `undefined` 表示保持原值；`header` / `form` 返回 `null` 会删除该键；JSON 返回 `null` 会写入 `null`。
- 脚本同步执行，默认超时 1000ms，可配置 50–5000ms。脚本异常保持原值，开启调试时仅记录错误阶段，不记录异常原文，不会中断正常代理。
- 为防止破坏响应，`content-length`、`transfer-encoding`、`connection`、`keep-alive` 不会被规则改写，`set-cookie` 数组也不会被改写。
- 命中响应正文规则时不会写入 fallback 预热缓存，避免把改写后的内容缓存成上游原始响应；关闭站点或删除规则后立即恢复原行为。

### 支付弹窗 URL 规则（一键预设）

- 场景：`/666/purchase` 里的“重新打开支付页面”不读请求参数 `return_url`，而是读创建订单接口 `POST /api/v1/payment/orders` 返回的 `data.pay_url`。所以只改请求里的 `return_url` 不会改变弹窗地址。
- 后台操作：编辑站点 →「请求 / 响应键值脚本」→ 点击「添加支付弹窗 URL 规则」。预设会自动生成一条响应规则：URL 正则为 `^/api/v1/payment/orders/?(?:\?.*)?$`，方向为响应，位置为 JSON 正文键，键为 `data.pay_url`。
- 把脚本中的 `https://example.com/replace-with-your-payment-url` 改成真正要打开的完整 HTTPS URL（包括必要 query）。如果目标地址需要签名参数，必须把签名后的完整 URL 填进去；这条规则只改变浏览器打开哪里，不会修改原站订单签名或支付状态。
- 保存站点后，对 `/666/purchase` 做强制刷新（Ctrl+F5），再下单或点“重新打开支付页面”。普通刷新可能继续使用浏览器缓存里的旧脚本或旧下单结果。
- 这条规则可以随时停用或删除；停用/删除后立即恢复原站的 `pay_url`。URL 正则不要带 `/666` 前缀，也不会匹配 `/api/v1/payment/orders/123/cancel` 之类的子路径。
- 调试时打开站点的调试开关，只记录命中和改写阶段，不会打印完整 `Authorization` / `Cookie`，也不会记录脚本异常原文。

### 支付弹窗转 VMQ 收银台

- 后台同一区域提供「添加 VMQ 收银台规则」预设。它也是修改 `data.pay_url`，但返回值不是固定 URL，而是本站公开入口：`/__ih/vmq/checkout/<站点 ID>?pay_id=<业务订单号>&price=<金额>&type=<1 微信 / 2 支付宝>`。
- 预设脚本会从原支付链接提取 `money` 和 `out_trade_no`，从下单请求体判断 `payment_type`；微信映射到 VMQ `type=1`，支付宝及其他映射到 `type=2`。
- 公开入口在服务端用 VMQ 通信密钥签名创建订单，成功后 302 跳转到 VMQ 收银台 `checkoutUrl`。浏览器看到的是 VMQ 收银台，不再打开原站 `api.zxspro.cn` 那条签名错误的链接。
- 服务端必须先配置 `IH_VMQ_API_ORIGIN`、`IH_VMQ_CHECKOUT_ORIGIN`、`IH_VMQ_CALLBACK_ORIGIN` 和 `IH_CALLBACK_VMQ_KEY`，并在站点编辑里开启「VMQ 回调适配」。生产环境当前使用本机 VMQ API `http://127.0.0.1:50126`、公开收银台 `https://hacket.top`，密钥保存在 `/etc/iframe-host/secrets/vmq.env`。只使用收银台时不要求发布回调模板。
- 公开入口有全局和单 IP 限流；它只创建收款订单并跳转，不验证到账，也不会给 8888ok 账户充值。回调和自动充值属于后续独立流程。
- 如果 VMQ 环境变量或站点开关缺失，弹窗会显示对应错误码；先检查服务端环境变量及站点 VMQ 开关，不要修改或伪造支付签名。

## 验证码与手动登录排查

- 多站点代理会给上游响应中以 `/` 开头的 `Location` 补当前站点前缀；已带前缀的路径不会重复添加，其他域名的跳转保持原样。例如 `/666/` 站点的 `/login` 跳转应变为 `/666/login`。此修复仅针对 HTTP 响应跳转，不代表所有 SPA 客户端路由已兼容。
- Cloudflare 验证失败不能只凭截图归因。需要检查验证脚本的网络加载、浏览器实际错误码、sitekey 允许的域名以及上游服务端验证配置。不要删除验证逻辑、伪造验证结果或通过响应替换让前端显示成功。
- 可见浏览器可以由用户本人在原站完成验证和登录；无头浏览器并不保证能完成交互验证。默认优先使用原站正常浏览器流程。
- 在原域名完成登录不等于代理域名自动登录。Cookie、localStorage、令牌、回调路径及验证环境可能不同；不能直接共享一个管理员账号的登录态给所有代理访客。本项目目前未实现浏览器登录态导入或后台浏览器托管。

## 2Captcha / Turnstile 站点配置

登录后台后，打开站点编辑中的「验证码服务」。每个站点可以独立开关，默认关闭。

- 服务商选择 2Captcha；只适用于已授权上游的普通、显式渲染 Turnstile 组件。
- `API key 环境变量` 填 `CAPTCHA_2CAPTCHA_API_KEY`，不能填密钥本身。密钥只保存在服务器受限环境文件中，后台不会显示或返回密钥。
- `Turnstile site key` 填组件的公开 sitekey，而非 Cloudflare secret key。
- 验证页面填上游路径（例如 `/login`），不要加代理前缀 `/666`。
- 默认超时 120 秒；每站点每小时最多 3 个任务，可设为 1–100。建议首次联调先设 1。
- 「检查已保存的验证码配置」仅检查密钥是否已加载、预算存储是否健康及本小时计数，不创建任务、不扣验证码费用。

本机安全配置服务器密钥（已有 `ops/.env` SSH 配置时）：

```powershell
python ops/configure-captcha.py
python deploy-current-fix.py
```

第一条命令通过不回显提示接收 API key，写入 `/etc/iframe-host/secrets/2captcha.env`（root:root，0600），并创建 systemd drop-in `/etc/systemd/system/iframe-host.service.d/30-captcha.conf`。脚本不修改站点开关、不创建任务；需要重启服务才生效。`--stdin` 仅供安全自动化内存传递，禁止将密钥写进命令行参数或 shell 历史。

Linux 服务通过直连访问 `https://api.2captcha.com`，不使用 Windows 工作站代理。预算文件为 `/var/lib/iframe-host/captcha-budget.json`，由服务账户写入。丢失预算文件会重置计数，不应当作日常清理文件；损坏或写入失败时停止新任务。单进程内去重，当前实现不支持多个服务进程共享预算文件。

开启后，原生优先模式先等待 10 秒，尚未成功才尝试付费兜底；仅服务商模式立即开始。一个页面最多发起一次任务；失败不自动重新创建任务，刷新页面可能再次消耗额度。额度在调用供应商之前持久化，网络失败也计入本地限额；此计数不是供应商实际账单。每站最多一个活动任务。

页面票据绑定站点配置及 HttpOnly 浏览器 Cookie，5 分钟过期。取得结果后写入响应字段并回调原站组件，不会伪造后端验证成功，不会向打码商发送用户密码，也不会导入或共享登录态。不要将启用服务的页面放入公共缓存。

不支持整页 Cloudflare 挑战、含 cData/chlPageData 的组件、隐式组件或验证脚本根本无法加载的情况。只使用 `getResponse()` 取值时需配置响应字段名或选择器并发生匹配的显式 render。修改 hostname、删除 div 或启用按钮不能保证后端接受验证。拿到 token 不代表登录成功，必须以实际登录接口结果验证兼容性。

联调先运行 `npm run check` 和 `node test-multisite-integration.js`（供应商模拟，不扣费），再检查后台状态。真实付费联调应明确确认次数，使用本人测试账号；不要输出 API key、完整验证码结果或 Authorization。关闭站点验证码服务即可停止后续新任务；已经提交供应商的任务不会被撤回。

### 修改登录页的提示文字

入口：「编辑站点 → 验证码服务 → 页面提示文字」，在「验证码兼容模式」下面、「高级回填设置」上面，默认直接显示，不需要展开高级设置。

| 配置项 | 示例 | 显示时机 |
| --- | --- | --- |
| 等待验证时的提示 | 正在验证，请稍候… | 适配器等待验证码服务时 |
| 验证完成后的提示 | 验证成功，请点击登录。 | 拿到服务商结果并完成回填 / 同步回调后 |

- 每项各自最多 200 字符，支持中文和 emoji，只按纯文本显示，不执行 HTML 或 JavaScript。
- 留空恢复内置默认提示，默认会根据浏览器语言显示中英文；自定义内容始终按原样显示，不自动翻译。
- 保存站点后，已打开的登录页仍使用旧配置，需要刷新才看到新文案。保存文字本身不创建付费任务；刷新启用服务的登录页可能创建新任务，请留意额度。
- 等待 / 完成下面增加折叠的「其他状态提示」，可逐项修改：结果失效、组件重置、服务忙、每小时额度用完、服务超时、页面会话失效、回填配置无效、密钥缺失、回调失败、服务商拒绝任务 / 无法连接 / 返回异常、额度存储错误、服务已关闭、内部错误以及其他未分类错误。
- 例如「结果已失效」填 `验证已过期，请重新打开页面验证。`，「服务忙」填 `已有验证任务正在处理，请稍候，勿连续刷新。`。这些文字不代表可以忽略验证码校验；不要把错误提示写成成功。
- 「其他未分类错误」仅在没有专属自定义文字或内置提示时兜底，不能覆盖正常的等待 / 成功 / 过期状态。留空时原有默认提示保持不变。
- 上述配置仅覆盖我们注入的验证码适配器提示，不修改原站组件的「验证等待时间较长」「验证未能加载或完成」及「重新验证」按钮。原站文案需另行配置站点替换规则并确认实际组件来源，不能把两种提示当成同一来源。
- 改文字不会延长验证码有效期、启用登录按钮、重新调用回调、重试付费或提高额度，也不会使现有验证票据失效。
- 「验证码服务忙」表示同站点有活动任务，或全局任务缓存达到容量限制；不要连续刷新。等已有任务结束后检查已保存状态、额度与诊断，再决定是否继续测试。

### 新手先看：按实际场景填写

登录后台，打开「站点列表 → 编辑 → 验证码服务」。右上方的「使用说明」也可以查看下面这些例子，中英文会跟随后台的全局设置切换。

界面分为「基础配置」「验证方式」「高级回填设置」。高级回填默认收起，通常不用填；已有选择器、字段名或回调配置时会自动展开，收起不会清空或停用这些值。费用提醒集中在底部；配置检查按钮只检查已经保存的配置，不发起付费任务。

#### 第一次配置：先留空高级选项

假设你访问的是 `https://hacket.top/666/login`：

| 页面选项 | 第一次怎么填 | 为什么 |
| --- | --- | --- |
| 付费服务开关 | 配置时先关闭 | 避免访客打开页面就开始花钱 |
| 服务商 | 2Captcha / Turnstile | 对应当前接入的服务 |
| sitekey | 使用原网站的公开标识，已有正确值就不改 | 不是自己起的名字，也不是服务商 API 密钥 |
| 上游页面路径 | `/login` | `/666` 是代理前缀，不要重复加进去 |
| 兼容模式 | 先看下一段，再选择 | 决定原控件先试，还是直接调用付费服务 |
| 超时 / 结果有效期 | 都先填 `120` 秒 | 一个是等待任务的时间，一个是结果最多保留的时间 |
| 每小时任务上限 | 测试先填 `1`，可设 `1–100` | 整个站点共用这个额度，不是每人各有一次；调高后可能增加费用 |
| 响应字段选择器 / 字段名 / 回调路径 | 三个都先留空 | 通常可以自动对接，不要照抄别的网站参数 |

**模式怎么选？**「原生优先」先让原控件试 10 秒，再尝试付费服务；原控件反复报错或清空结果时，可以试「仅服务商验证（强制兼容）」，匹配到组件后立即付费验证。这不是强行启用登录按钮，也不能跳过原网站后端检查。

**填完怎么测试？**先保存，再点「检查已保存验证码配置」：这一步不扣费、不查余额，只看本地配置是否就绪，不保证能验证成功。密钥需要管理员另行安装，表单只填环境变量名称，不要粘贴密钥本身。准备好付费测试后才开启、保存、刷新登录页。结果就绪后，由用户自己点登录；以原网站返回判断成功。关闭并保存会阻止新任务，但已提交任务仍可能收费。

#### 高级选项：用三个例子分清楚

1. **已有输入框，用选择器。**假设页面有 `<input type="hidden" id="captcha-token" name="verification">`，选择器填 `#captcha-token`，表示把结果写进这个已有输入框。若源码只有 `<div id="captcha-token">`，那只是外面的盒子，不是提交值的字段，不能照搬这个 ID。指定选择器找不到输入框时，不创建任务。
2. **只知道提交的字段名，用字段名。**假设网站需要 `verification`，选择器留空，响应字段名填 `verification`；系统寻找或创建这个名字的隐藏输入框。两项同时填时，以选择器为准。输入框有值，不代表网页内部状态已经更新。
3. **网站真的提供全局函数，才填回调路径。**你要找的是网页中接收验证码结果的函数，而且必须能通过 `window` 访问，不是任意一个 JS 内部函数。

   假设网页已经有下面的函数（只是演示接收参数，不代表设置这个变量就能登录）：

   ```js
   window.app = {
     onVerified: function (token) {
       window.receivedToken = token;
     }
   };
   ```

   后台填 `app.onVerified`。取得真实服务商结果后，相当于调用 `window.app.onVerified(token)`，验证码结果就是传进去的参数。点号的意思是“app 里面的 onVerified”。如果函数直接叫 `window.handleCaptcha`，就填 `handleCaptcha`，不用点。后台不填 `window.` 前缀、不加括号、不写 JS；函数必须实际存在，不要自己编名字。

   **“保留原组件回调”是额外通知，不是替换。**例如网页初始化时写了 `turnstile.render(container, { sitekey: publicKey, callback: pageVerified })`，原回调就是 `pageVerified`。拿到服务商结果后，系统仍先调用 `pageVerified(token)`；如果额外配置了 `app.onVerified`，还会把同一个结果传给它。原回调可能负责更新网页验证状态，不能因为增加自定义接收函数就丢掉它。

   通常留空就能保留原回调。如果你找到的函数本来就是原回调，不必再填，避免重复执行业务逻辑。框架内部函数通常不能用全局路径指定；收到结果也不代表后端登录成功。

#### 出问题时看诊断日志，不要反复刷新碰运气

先在「编辑站点 → 调试与资源控制」开启「站点调试日志」并保存，再刷新需要排错的站点页面。然后在「编辑站点 → 验证码服务」底部，点「检查已保存的验证码配置」，展开「验证码诊断日志」。这只读取记录，不创建付费任务。

- 先看**已保存服务开关**，不是只看“验证方式”。选了“仅服务商”但服务开关仍关闭，适配不会运行。表单与已保存开关或模式不一致时会提示先保存；检查按钮不会替你保存。
- **暂无日志**不等于验证成功或失败。开关关闭时本来就不注入脚本；开启后仍没有记录，需检查 `/__ih/captcha/client.js` 是否加载，或诊断上报是否被浏览器拦截。
- 先找“适配脚本已加载 → 已接管原组件 render → 网页调用了 render → 组件与配置匹配”。只走到前几步，重点看路径、sitekey、组件 API 或脚本时序，不要先找全局回调。
- 再找“服务商任务已创建 → 服务商已返回结果 → 浏览器已收到结果 → 网页原回调已返回”。如果记录本小时额度用尽、密钥未配置、任务超时等错误，先处理对应错误，不要盲目提高额度或反复刷新。
- **“原回调已返回”只表示调用返回时没有同步异常**，不保证内部异步操作成功、按钮亮起或后端登录成功。浏览器上报也不是独立的服务端验证证据。

后台最多展示本站最近 50 条记录；内存里全局最多保留 1000 条，服务重启会清空。相同日志也写入服务日志，保留期限由系统日志策略决定。浏览器日志标注“浏览器上报”，服务商任务记录标注“服务器”；短页面编号只用于区分访问，不包含票据或 Cookie。日志只接收预定义事件，不保存密码、Cookie、请求头、验证码结果或异常原文；浏览器每页最多上报 40 个不同阶段，服务器每票据最多接受 48 条，诊断上报不占付费额度。

管理员可用 `journalctl -u iframe-host.service --since "30 minutes ago" --no-pager | grep '^.*\[captcha\]'` 查看服务日志。页面还可通过开发者工具查看 `window.__ihCaptchaDiagnostics`；该数组只有事件名与时间，不含真实验证码结果。测试用模拟供应商验证，不会为检查日志而额外调用付费接口。

#### 常见疑问

- **“清空回填结果”是坏了吗？**不是。结果过期、组件重置或移除时，清掉旧结果是为避免提交过期值。默认最多保留 120 秒，设置更长也不能延长原网站的有效期。不会自动再付费一次。
- **提示结果就绪，按钮还是灰的？**先确认网站接收结果的字段和回调，不要只删 `disabled` 或验证码框。打码任务成功不等于网页登录成功，更不等于后端接受了登录。
- **失败了能一直刷新吗？**不建议。每页最多创建一个任务，但刷新可能再花钱；失败或创建结果不确定也占用本地次数。先看提示，别盲目提高限额。
- **任何 Cloudflare 页面都能用吗？**不能。这里只对接支持的普通独立 Turnstile 组件；整页浏览器检查、脚本无法加载等情况不适用。具体限制见下方技术参考。

以下是给管理员排查问题用的技术参考，普通使用不需要逐项研究。

### 验证码兼容模式与自定义适配

后台「编辑站点 → 验证码服务」新增兼容模式：

- `native_first`（默认）：原生优先，等待 10 秒后尝试服务商。真实打码结果有效期间，不让原控件的错误/超时/过期/不支持回调覆盖成功状态。
- `provider_only`（仅服务商验证 / 强制兼容）：只对匹配页面、sitekey 的显式组件跳过原生 render，立即请求服务商。不再显示该组件的原生报错框，保留应用原有成功回调。不是修改后端验证、伪造 token 或强制启用登录按钮；需要原生 API 脚本可加载及应用执行显式 render。

适配字段（通常全部留空即可）：

| 配置键 | 用法 |
| --- | --- |
| `response_selector` | CSS 选择器，指向已存在的隐藏/文本 input 或 textarea，可匹配多个；例如 `input[name="cf-turnstile-response"]` 或 `#captcha-token`。不是外层 div。无效或找不到字段时不创建任务。 |
| `response_field_name` | 自动创建/寻找隐藏 input 的 name，默认沿用组件 `response-field-name` 或 `cf-turnstile-response`。配置 selector 时以 selector 为准。 |
| `callback_path` | 额外的已有全局函数路径，如 `app.onVerified`；接收真实 token 并保留函数 this，不接受任意 JS。组件的原有回调仍会执行，Vue/React 内部闭包无需手动填写路径。 |
| `result_ttl_seconds` | 本地结果有效期上限，默认 120 秒，可设 30–240 秒。不能延长服务商/上游实际有效期，且 token 只能按上游规则使用。 |

匹配组件的 `getResponse`/`isExpired` 一并适配；reset/remove/页面卸载及本地过期都会清空缓存结果。过期和 reset 通知原过期回调，状态文字同步更新；不会自动创建第二个付费任务。不得仅凭隐藏 input 有值判断登录成功，必须以应用正常提交和后端结果为准。不支持任意验证码类型的自动转换，也不做账号密码抓取或自动登录。

`/666` 实测还需要 SPA 路由基路径适配：当前上游构建含 `history:qr("/")`，站点 literal 替换为 `history:qr("/666/")` 后才会停留在正确登录路由。此规则是特定构建的站点配置，不是通用编译产物规则；上游升级后需要重新核对，不能声称对所有 Vue 站点自动适配。
