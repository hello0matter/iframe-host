# 收款回调与前后端脚本模板设计

2026-11-18 已实现通用外部回调的模板 CRUD、版本发布、站点绑定、签名 JSON 桥接接收、持久任务、受限后端 / 隔离前端步骤串联，操作见 `EXTERNAL_CALLBACKS.md`。下文的支付平台原生适配、真实收款核验、原站 DOM 自动化、受控后端网络能力和自动充值仍为后续设计，不能据此认为已经上线。API 透传与回调开关相互独立。

## 原站支付渠道调查

2026-11-18 只读读取原站公开首页及其引用的前端资源，没有登录、创建订单、扫码或付款。前端包含 `official_alipay`、`easypay_alipay`、`official_wxpay`、`easypay_wxpay` 等渠道名称，并引用 Stripe / Airwallex 支付页面。这只能证明前端包含多渠道适配，不能证明当前支付宝订单实际使用了哪一家网关。用户提供的 `payment_source: hosted_redirect` 也不足以唯一确认网关。

下一步需要现有订单的脱敏创建响应 / 支付跳转地址，或实际收款平台的文档与商户配置。不要重新下真实订单仅为识别平台；不要把密码、Authorization、签名或商户密钥粘贴到文档。原站的商户密钥与商户回调不会因为本站做反向代理就自动归本站所有；是否能指定通知地址必须核对真实平台协议。

## 模板的增删改查

后台独立“回调流程模板”页，模板包含名称、说明、适用站点、草稿版本、已发布版本、总开关和步骤列表。可新建、查看、编辑、复制、停用及删除未被引用的模板。已绑定订单的版本不可原地修改；删除有历史引用的模板应归档，保留订单追溯。每站绑定一个已发布模板；默认关闭，保存草稿不执行。

每个步骤可选择 `server_node` 或 `browser_js`，有独立开关、超时、允许调用的能力和输出字段映射；可按后端 → 前端 → 后端排序。脚本返回结构化数据给下一步，而不是共享 Node 进程或隐式共享 window。示例：后端标准化已验签通知 → 后端创建充值任务 → 前端显示进度 / 执行明确允许的页面动作 → 后端查询原站实际到账。

## 收款事件必须先经过不可跳过的校验

支付平台通知 → 平台适配器按官方协议验签 / 必要时主动查单 → 核对本地订单、站点、商户、币种、整数金额、支付状态 → 持久记录已确认支付事件 → 创建幂等流程任务 → 按真实平台协议返回确认。

前端付款完成跳转不是支付通知，浏览器回传“成功”也不是收款证据。模板不能通过 return true 跳过固定校验，不能自己修改“已支付”事实。平台允许如何返回 ACK、如何签名、是否通知原始请求体，都由真实适配器处理，不假定一种通用 pay 协议。

以站点、渠道、商户、交易号及事件号建立唯一约束；重复通知返回该平台规定的确认但不重复充值。事件和任务必须可靠落盘后才确认通知。执行任务不阻塞平台通知响应；重复执行是否安全取决于每个外部动作的幂等支持。

## 后端 Node 与浏览器 JS 的界限

- 后端运行在独立的受限进程 / 容器中，通过受控能力接口获取所需资源，不给脚本主服务 require、process、文件系统、命令执行和全部环境变量。单纯 Node vm 或一个 Worker 不是此处的安全隔离方案。
- 商户密钥由服务端环境变量或加密存储引用，只由平台适配器使用；不送入前端、不放进模板正文、上下文返回值或日志。后端出站请求限制固定域名、方法、响应大小及时间，禁止任意内网目标。
- 前端步骤默认只执行展示类动作。需要页面交互时，绑定明确的站点、用户会话和订单；只有已认证、授权且在线的对应浏览器能领取任务。任务有短时单次凭证，不在所有访客页面广播执行。
- 浏览器没有在线会话时进入 waiting_browser，不会假装执行成功。用户可看到暂停原因，选择继续或转人工；不得强制保存用户密码或把其他用户会话拿来执行。
- 前端只接收脱敏字段和所需任务数据；浏览器回报视为不可信观察结果。后端仍通过可靠的原站订单状态或人工核验确认到账。
- 已发布代码是高权限操作：需要管理员权限、发布确认、版本记录及操作留痕；不允许支付通知直接提交代码并执行。

## 状态、重试与开关

订单状态分开保存“本站收款事实”和“原站充值进度”。收款已确认、待充值、执行中、等待浏览器、待核对、成功、失败、转人工均可独立展示。收到钱但原站充值失败时，不能显示全流程成功。

每步持久记录输入摘要、版本、结果和执行时间，日志脱敏且受数量和保留期限制。对外调用超时但无法判断是否生效时进入待核对，不盲目重试扣款 / 充值 / 扫码。重试必须先查单或使用对方支持的幂等键。停止流程开关不丢弃已收到的有效支付通知，而是暂停后续动作并提示管理员处理。

第一版调试使用本地虚拟支付适配器与模拟回调：覆盖错误签名、金额不符、不同站点、重复通知、重启恢复、无浏览器、前端伪造成功、步骤失败和执行结果未知。付费渠道、自动扫码和真实原站充值须另行对接并验证；不承诺仅凭通用脚本即可实现。
