Identity and route

External callback binding

Default off. Publish a template in External callbacks, then paste its ID here. Receive URL: /__ih/callback/SITE_ID. Signed JSON or VMQ notification adapters. Never paste a secret here.

VMQ receive URL: /__ih/callback/vmq/SITE_ID (use your public HTTPS domain). Store the VMQ communication key in this server environment variable, not in this form. Both receive switches must be on. Duplicate deliveries do not create another task. ACK means received, not upstream recharge completed. Scripts still have no network or original-site DOM access.

Admin Worker is data calculation only. User page refresh requires page_ref + order_ref binding. Notifications default off and never broadcast. No arbitrary page JS or payment actions. Signing secrets stay server-side (32+ bytes).

API passthrough

Default off. /v1 matches /v1 and /v1/... but not /v10. Do not include the site proxy prefix. / matches the entire site. API responses bypass page rewriting, captcha, response scripts, body audit and fallback cache. No API key is supplied automatically.

Advanced API options

Timeouts: 1–3600 seconds, default 120. Response bytes are streamed without editing; client disconnects cancel forwarding. No automatic retries, CORS bypass, WebSocket support or payment callbacks are added.

Debug and resource controls

Replacement rules

Rules are applied in order before standard proxy URL rewriting. Use literal for ordinary text or URL substitutions; choose regex only when the pattern is a JavaScript regular expression.

Request / response value scripts

Choose request or response, then a value location. When the upstream URL matches, the script replaces the selected value. Request rules run before forwarding; response rules run after the upstream replies.

For the "Reopen payment page" popup, edit the response rule for JSON key data.pay_url, not request return_url. Put the complete new HTTPS URL in the returned value; keep the demo's query parameters only if the destination accepts them.

URL intercept script

When a request URL matches the pattern, the proxy skips the upstream request and runs the JavaScript below. The script can read request.method/path/query/url/headers/cookies/body, and must return a string or an object with status, headers, body and content_type.

Verification service

Get a real verification result for supported Turnstile widgets. You still sign in yourself.

Basic configuration

Verification behavior

Native first waits 10 seconds before paid fallback. Provider only starts paid verification immediately for a matching widget.

Page status messages

Customize adapter status messages above the login button; expand Other status messages for expiry and errors. Plain text, up to 200 characters each; blank restores defaults. Save and reload to apply. Original-site messages and retry buttons are separate. Text changes do not change verification state, quotas or charges.

Other status messagesOptional · blank restores defaults

Keep failure messages truthful: expired or failed verification is not successful. These fields only change our adapter text, not the original site message or retry button.

Advanced response settingsOptional · usually leave blank

Only configure these if the site needs a specific response field or an extra global callback. The original callback is still called.

Paid usage

One paid task per page. Refreshing may cost another; failed tasks are not retried automatically. A verification result does not guarantee login.

Checks saved settings only · no paid task
Verification diagnostics

Browser entries are client reports, not proof of login. Recent entries reset when the service restarts; server journal entries follow system retention. No passwords, cookies or verification tokens are recorded.
